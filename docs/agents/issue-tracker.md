# Трекер задач: GitHub

Задачи и спецификации хранятся в GitHub Issues репозитория
https://github.com/MeNn13/wip. Используй CLI `gh` с явным
`--repo MeNn13/wip`.

## Операции

- Прочитать задачу: `gh issue view <номер> --repo MeNn13/wip --json number,title,body,labels,comments`.
- Найти задачи: `gh issue list --repo MeNn13/wip --state open --json number,title,body,labels`;
  при необходимости добавляй фильтр `--label`.
- Создать задачу: `gh issue create --repo MeNn13/wip --title "..." --body-file <файл>`.
  Многострочный текст передавай через UTF-8 файл.
- Добавить комментарий: `gh issue comment <номер> --repo MeNn13/wip --body-file <файл>`.
- Добавить или снять метку: `gh issue edit <номер> --repo MeNn13/wip --add-label "..."` или `--remove-label "..."`.
- Закрыть задачу: сначала опубликуй объяснение отдельным комментарием,
  затем выполни `gh issue close <номер> --repo MeNn13/wip`.
  Для уже закрытой задачи также используй отдельный комментарий.

Перед первой записью в трекер за сессию проверь целевой репозиторий:
`gh repo view --repo MeNn13/wip --json nameWithOwner`.
Если цель отличается, остановись и уточни её у пользователя.
Задачи проекта создавай только в `MeNn13/wip`.

## Подзадачи и зависимости

Используй нативные подзадачи и зависимости GitHub, если они доступны.
Поддерживаемые команды проверяй через `gh issue create --help`
и `gh issue edit --help`.

Если подзадачи недоступны, добавляй `Part of #<родитель>` в начало
описания подзадачи и ссылку на неё в список задач родителя.

Если нативные зависимости недоступны, записывай
`Blocked by: #<номер>, #<номер>` в начале описания зависимой задачи.
Задача готова к началу, когда все блокирующие задачи закрыты.
При проверке нативных зависимостей учитывай только открытые блокеры.

## Обращения через pull requests

Разбор внешних pull requests как запросов на работу: выключен.

## Указания других навыков

«Опубликовать в трекере» означает создать GitHub Issue.
«Получить связанную задачу» означает прочитать соответствующую Issue.

## Навигация по работе

Для `/wayfinder` карта работы — одна Issue с дочерними задачами.
Карта использует метку `wayfinder:map`, дочерние задачи —
`wayfinder:research`, `wayfinder:prototype`, `wayfinder:grilling`
или `wayfinder:task`. Эти метки создаются при необходимости
в рамках отдельного запуска навыка.

Следующей выбирай первую по порядку карты открытую задачу без
открытых блокеров и исполнителя. При взятии задачи назначь её на себя.
После решения опубликуй результат комментарием, закрой задачу
и добавь краткий вывод со ссылкой в решения карты.
